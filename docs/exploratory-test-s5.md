# 탐색적 테스트 (S5, 세션 기반)

자동화 테스트가 보지 않는 것 — 화면이 설계와 같은지, 실제로 쓰는 순서에서 이상이 없는지 — 를 사람이 직접 써 보며 찾는다. 세션 기반 탐색적 테스트(SBTM) 방식으로 시간 상자를 두고, 한 줄씩 노트를 남긴 뒤 디브리프에서 판정했다.

- 노트 형식: `시각 | 한 것 | 기대(출처) | 실제 | 판단`
- 기대 칸에는 근거 문서를 적는다 — 화면설계서(SCR-n), 요구사항(REQ-n), 보안 점검 기록([security-check.md](security-check.md))
- 판단: OK / 버그 / 질문(디브리프에서 판정) / 시험 안 함
- 환경: 로컬 Docker DB(`local-docker`), 백엔드 `bootRun`, 화면 `npm run preview`, Chrome, 1024×768(매장 태블릿 가로 기준)

## 차터

| # | 범위 | 목적 |
|---|---|---|
| 1 | SCR-1 로그인 1:1 대조 | 화면 이미지·문구·상태 처리가 설계와 같은지, 세션 만료 뒤 동작 |
| 2 | 핵심 3건 | 보안 점검 '입력값 검증'의 화면 확인(스크립트 페이로드가 글자로 보이는지), 충전 취소 거절 창 [닫기] 색, 메모 칩 터치 영역 |
| 3 | SCR-3~10 빠른 대조 | 화면 공통 규칙(파란 강조·모달 닫기·검색어 주소 금지)과 문구·동작 |

## 디브리프 — 질문 줄 판정

| 항목 | 판정 | 처리 |
|---|---|---|
| 세션 만료 안내가 두 줄 (SCR-1) | 버그 | CB-54 — 화면을 설계(한 줄)에 맞춤 |
| 없는 고객 문구 (SCR-10) | 버그 | CB-55 — 화면 문구를 설계 문구로 |
| 서버·네트워크 오류 문구 (SCR-10) | 버그 | CB-56 — 서버 오류 문구는 설계 문구로, 네트워크 끊김 문구는 남기고 설계서에 줄 추가 |
| 충전·사용 창 두 번째 열기부터 커서 없음 (SCR-6·7) | 버그 | CB-57 — 재발 방지 테스트는 두 번째 열기까지 본다. 설계서에 '입력 창을 열면 첫 입력 칸에 커서' 규칙 추가 |
| 로그인 버튼 비활성 색 (SCR-1) | 문서 수정 | 화면 유지(주 버튼 색을 흐리게), 설계 이미지를 맞춤 |
| F5 때 만료 안내 없음 (SCR-1) | 문서 수정 | 쿠키가 없으면 '만료'와 '처음 접속'을 구별할 수 없어 안내 없이 로그인 화면 — 설계서에 명시 |
| 고객 등록 폼 위치 (SCR-4) | 개선 후보 | 지금은 설계대로. 프로젝트 종료 후 후보 |
| 취소선 없음 (SCR-8) | 유지 | 금액이 그대로 읽혀야 장부를 추적할 수 있다는 설계 결정 그대로 |
| 기기 흉내 모드에서 오프라인이 안 먹힘 | 기록만 | 앱 결함이 아니라 개발자 도구 설정 문제로 추정, 원인 미확인 |

## 결과

- 발견한 결함 4건(CB-54~57) — 모두 화면 결함, 장부·잔액에는 영향 없음. 수정은 S6
- 문서 수정 3건(SCR-1 버튼 비활성 색, SCR-1 F5 만료 안내, SCR-10 네트워크 끊김 문구)
- 보안 점검 '입력값 검증'의 화면 확인 완료 — 서버 쪽은 통합 테스트 TC-22로 고정
- 시험하지 않은 것: 확인 화면에서 다른 기기 차감 뒤 막힘(SCR-7), SCR-3·4·5 화면 대조, 모달을 열 때 브라우저 콘솔의 aria-hidden 경고 재확인(CB-57과 같은 원인으로 보여 수정 뒤 확인)
